Purpose: what current Google guidance requires for a small Next.js apparel store, and how each point maps to the KVRN code. **Crawlable ≠ indexed ≠ ranking.** Nothing here claims any KVRN URL is indexed or ranks; that needs Search Console evidence (see `SEO_ACCOUNT_RUNBOOK.md`).

## What the sources establish
| Finding | Source | KVRN status |
|---|---|---|
| Variants are modelled with `ProductGroup` (shared attributes, `productGroupID`, `variesBy`) containing `Product` variants (unique `sku`/`gtin`, each with its **own** Offer price + availability). On multi-page sites each page repeats the complete markup. | 1, 2 | **Not implemented, deliberately.** The PDP emits one `Product`. A truthful `ProductGroup` needs per-variant availability; today `hit.availability` is product-level (any stock). Emitting per-variant offers from that would invent stock. See "Proposed next step". |
| Variant URLs must be crawlable and show the right price/availability. | 1 | KVRN variants are client-side selections on one URL; no per-variant URL exists. Another reason to keep a single `Product` for now. |
| Product markup generated by JavaScript may be crawled less reliably; prefer it in the initial HTML. | 1 | **OK.** JSON-LD is server-rendered into the HTML (verified by `scripts/seo-crawl.mjs`). |
| Apparel offers in Merchant Center need `gender`, `age_group` and `color`; an inaccurate category changes which attributes are required. | 3 | **Gap.** The current feed (`lib/google-merchant-feed.ts`) is a conservative *product-level* baseline (id, title, description, link, image, price, availability, condition, brand). It omits those attributes; expect Merchant Center "missing value" diagnostics for apparel until a variant feed (below) exists. The code header already lists this as a launch gate. |
| Shipping/returns can be declared in Search Console / Merchant Center and via organisation-level return-policy markup. | 5 (title only) | **Not implemented.** No `MerchantReturnPolicy`/`ShippingPolicy` markup is emitted. It must mirror the **approved** shipping & returns policy (owner/legal review pending), so it is not added now. |

## What was checked in the code (no external calls)
* `app/robots.ts` — allows `/`, disallows `/admin`, `/checkout`, `/api/`; references the sitemap. Media is served from `/media/…` (not blocked), so images stay crawlable.
* `app/sitemap.ts` — 12 URLs locally (home, shop, 2 products, about, contact, FAQ, shipping-returns, size-guide, privacy, terms, project-kvrn collection). No duplicates, none disallowed by robots, none noindex. Note `/cookies` is **not** in the sitemap (intentional or oversight — owner decision; low value either way).
* Canonicals: PDP/policy/support pages already had them; **home, `/collections/*`, contact, size-guide** were missing or inheriting the site description — fixed in this branch.
* Structured data: site-wide `Organization` (type `ClothingStore` from Admin SEO); PDP `Product` with offer only from canonical price and availability **omitted when unknown**; coded (flag-off) catalog emits **no** Offer. Added `BreadcrumbList` (PDP, CMS collections).
* Open Graph / Twitter: product pages had a product OG but the site-wide Twitter title; fixed. **No default share image is configured** (see baseline) — owner action.
* Checkout: `robots.txt` blocks it but `/checkout/success` returned `index, follow`; added a `noindex` layout.
* GA4: browser GA only after effective analytics consent (DNT/GPC respected), Consent Mode advertising signals always denied, `send_page_view:false` with one deduped `page_view` per route; **purchase is server-side only** from the Stripe webhook with `transaction_id` = KVRN order number and value from the finalized order (no browser purchase ⇒ no duplicate). Microsoft Clarity is disabled in `app/layout.tsx`. Reviewed `lib/ga-client.ts`, `lib/ga4-server.ts`; 232 existing GA tests pass.

## Proposed next step (needs owner approval — touches inventory read paths / feed)
Variant-level Merchant feed + truthful `ProductGroup`: read `product_variants` (`sku`, `size`, `color_code`, `stock_on_hand − reserved_quantity`) **read-only**, emit one item per variant with `item_group_id`, `color`, `size`, `gender`, `age_group`, `identifier_exists=no` (no GTINs exist — never invent one), per-variant availability. Requires owner decisions: gender/age_group values, Google product category, GTIN/MPN policy. No migration needed. Not built yet to avoid asserting facts the owner has not supplied.
